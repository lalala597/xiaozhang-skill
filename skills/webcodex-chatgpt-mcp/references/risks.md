# 风险详解：给用户的安全说明书

向导 agent 按"30 秒版本"口头讲；用户追问或要做授权决策时，展开对应小节。

## 30 秒版本（对小白讲的话）

"三句话：

1. **挂上的目录，AI 全都能读**——读取不受任何保护，回退救不了已经被读走的内容。所以私人日记、别人的聊天记录别挂。
2. **AI 写不坏你的库**——它改的是一份平行副本，你本机点『接受』才真正落盘，之前随时可以整单拒绝。但有个例外：它能执行命令（run_shell），这条路的保护比文件编辑弱。
3. **开关永远在你手里**——命令行一键停掉全部服务（AI 立刻断线），也可以单个目录摘除。停了就等于什么都没发生过（除了已经读走的部分）。"

## 详细边界（实测确认过的事实）

### 能挡住的

- **目录边界**：Server 不扫描磁盘。只有 Runner 显式注册过的目录对 AI 可见，其余完全不可见。`allowed_roots` 再限定一层可注册的父目录。
- **写入隔离（双保险）**：编辑发生在目标仓库之外的隔离 Git worktree；真实目录只在所有者本机执行 `webcodex task accept` 后改变；`task reject` 则副本直接丢弃；隔离准备失败时 fail-closed（绝不退化成直写）。
- **模型不能自己 accept**："模型绝不能自己接受工作"是文档明文。
- **Git 回退**：每个项目都是 git 仓库，accept 后仍可 `git checkout` 回退。

### 挡不住的（必须让用户心里有数）

- **读**：挂上的库 AI 能全量读。1993 篇外部内容和私密叙事在隐私上完全不同，挂载清单要逐个过目。
- **命令执行**：工具清单含 `run_shell` / `run_script` / `run_process` / `run_job`，是"有界但强大的逃生口"，隔离强度低于文件编辑（文档措辞只承诺编辑走 worktree）。敏感库建议控制挂载范围而非指望这条防线。
- **read_only 可升级**：read_only 任务在"隔离准备成功后可升级为 normal"，且 normal 不能降级。意味着 AI 可能请求升级——挂载后第一件事是实测升级是否需要人工批准。
- **在线即入口**：三个进程（Server/Runner/隧道）在跑，入口就开着。不用时 stop。
- **备份解决的是完整性，不是保密性**：备份能恢复文件，救不了已经被读走的内容。

### OAuth scope 的特别说明

授权页会列出 WebCodex 声明的全部 scope（26 个），其中 `account:manage`、`computer:control`、`computer:launch`、`ssh:local`、`mcp:local` 属于高危项。要点：

- 这些 scope 是 WebCodex 声明的能力上限；文件读写实际被锁定在已注册目录内。
- 外部内容（别人写的文章）可能携带提示注入指令，诱导 AI 调用高危 scope——这是这套架构里最现实的攻击面。
- 缓解：不挂来源不明的外部内容库；观察期只用于知识库问答；发现异常立即撤销（见下节）。

## 提交前的数据卫生（部署时做一次）

- 每个待挂目录：git 仓库 + 工作区干净（未提交改动不在保护链里）
- 扫描待提交内容有无硬编码 token/密钥
- 私密目录单独评估，不顺手全挂

## 撤销开关（必须交付给用户）

```bash
# 临时全部断线（AI 立刻失联，文件不受影响）
bash <skill目录>/scripts/setup.sh stop

# 摘除单个目录：从 runner.toml 删除对应 project 段 → 重启 Runner
# 彻底吊销 ChatGPT 侧授权：webcodex 里 revoke OAuth client / 删除 PAT
# 彻底卸载：npm uninstall -g @yyjeqhc/webcodex && rm -rf ~/.config/webcodex ~/.local/share/webcodex
```

一句话给用户：**"把 stop 命令记在备忘录里，任何时候感觉不对，跑一下它。"**
