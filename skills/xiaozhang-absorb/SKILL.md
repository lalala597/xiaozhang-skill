# 小张Skill · 认知差值探测器

学习不是读完，是闭环：**没压成块的学习等于没学，没验证过的块等于没吸收。**

三道硬闸门贯穿全程：

1. **不分诊不开学**——先定卡点和层级，再决定学什么
2. **不压块不算学完**——每轮学习必须产出候选积木块
3. **不验证不转正**——自验升级、市场验证转正，跳过验证的块永远是候选

> 思考预算的分配：执行中像机器（照做，不让自己未校准的判断中途插手），
> 两头像科学家（选择和过滤时全力思考，对照结果时全力思考）。
> 「一模一样复制」是有截止日期的阶段——到能稳定复现对方结果为止，之后每次偏离都是可归因的受控实验。

## Phase 0: 分诊（每次必跑，5 分钟内完成）

三个问题：

**1. 对象是什么？**
人（有语料全集、要造可咨询的顾问）→ 停，路由 `人物蒸馏器`。
物（方法/作品/仓库/文章/课程）→ 继续。

**2. 我卡在哪？**
有具体卡点 → 只学解决当下卡点的那部分，直接跳 Phase 2 拆解。其余的不收藏、不焦虑。
无卡点、要系统进入新领域 → 先建最少必备知识骨架，走 Phase 1 学习梯度。

**3. 这个对象的价值在哪层？我该吸哪层？**

| 层 | 特征 | 吸法 |
|---|---|---|
| 招式（技法/数据） | 公式表、清单、模板、参数 | 直接拿来用，不值得「学」，登记出处即可 |
| 方法论（框架） | 流程、结构、判定规则 | **重点拆解对象**，走完整管线 |
| 操作系统（心法） | 跨场景不变量、决策函数 | 不能从单一作品吸——OS 只能从多样本拟合；样本不足时降级吸方法论层，不要硬抽（硬抽的产物是空抽象） |

> 空抽象自检：提炼出的「心法」若不能预测作者下一步、不能再生成他的招式、不能预言招式何时失效——那是口号，不入库。

输出一行分诊单：`对象 / 卡点 / 目标层 / 走哪条线`，然后开工。

## Phase 1: 学习梯度（系统学习模式）

> 参考交互式学习的反馈梯度机制，关键改造：**边学边压块**。

### 目录

默认 `小张外部知识库/学习课题/{课题名}/`（用户指定目录优先）：

```
{课题名}/
├── 00-学习计划.md      # 学习目标(写成可检查的能力)、路径、进度指针、反馈摘要表
├── 01.md, 02.md, ...   # 学习文章，文末固定反馈区
└── 候选块/             # 边学边压的积木块
```

### 文章结构

每篇固定：这一篇解决什么 → 正文 → 小结 → 下一篇预告 → **学习反馈区**。
反馈区留四个提示问题（哪里懂了/哪里没懂/想展开什么/和我的真实问题什么关系），小张读完直接在文件里写。

### 梯度规则

生成下一篇前**必须**：读上一篇反馈区 → 过滤模板提示行，只有小张新写的字算反馈 → 查表调梯度：

| 反馈信号 | 下一篇处理 |
|---|---|
| 没看懂、概念乱 | 降抽象度，补例子，放慢 |
| 懂了但没意思 | 换切入角度，连接真实问题 |
| 懂了，提应用问题 | 上案例和判断方法 |
| 明显掌握 | 提概念密度，进下一层 |
| 提出具体问题 | 先回应问题，再推进课程 |
| 反馈很少 | 保持难度，小步推进 |

找不到反馈时先问，用户明确说继续才写，并在开头注明「本篇未基于反馈」。

### 闸门 2 在这里执行

每篇文章生成时，同步把本篇核心压成 1-2 张候选块存入 `候选块/`（格式见 Phase 2.4）。
**文章是给人读的，块是给系统用的，缺一不可。** 只有文章没有块 = 这一篇没学完。

## Phase 2: 拆解吸收（核心工序）

对准 Phase 0 锁定的层，五步：

### 2.0 认知差值检测（先跑这一步）

绝大多数工具在这一步做「提取重点」。不要提取重点——**做差值检测**。

把用户在某个具体问题上的判断，和材料作者在**同一个问题**上的判断并排放，分四类处理：

| 情况 | 处理 |
|---|---|
| 用户知道，作者也同意 | **过滤掉**（无信息增量） |
| 用户知道，但作者不同意 | **最高优先级**——这才是认知差值 |
| 用户没有答案，作者提出新变量 | 进知识候选，标 `UNKNOWN` |
| 表面矛盾，但双方边界不同 | 标为**边界张力**，挖双方隐含前提 |

> 核心规则：**「已知」不该被过滤，只有「已知且一致」才该过滤。**
> 「已知但相反」恰恰要升到最高优先级——用户一端已经明确，最容易形成高质量差值。

#### 边界张力：不要急着判谁对

两个判断看起来直接冲突时，先别裁决，先挖前提。大多数「冲突」其实是**双方在不同边界内各自成立**：

- 作者的适用范围是什么？他没说出口的前提是什么？
- 用户的适用范围是什么？
- 两个范围真的重叠吗？不重叠 → 是边界张力，不是冲突。

产出必须写清：`作者的边界 / 用户的边界 / 是否真冲突 / 缺失的那座因果桥`。

#### 四路候选通道（并列扫描，不压成一个分）

只走「与用户目标相关」这一路，会漏掉用户真正停下来的地方。四路并列：

1. **明确差值**：双方在同一问题上都有判断，严格比较。
2. **材料内部异常**：隐含前提、因果缺口、概念重分类——只看材料本身即可触发。
3. **目标缺口**：可能解释用户现实中为什么没做成。
4. **已知概念的新关系**：双方一致，但出现了新的实现形式或新变量。

四路分别标注来源，不要合并成单一分数排序。

#### 三条铁律

- **没有用户的判断时写 `UNKNOWN`，不准替他编。** 编出来的信念会让整条管线产出假冲突。
- **不要把「和你项目有关」当成「你会感兴趣」。** 客观重要、可行动、主观有兴趣是三个独立变量。
- **不要强行把每个候选收束成行动。** 一个只造成世界模型冲突、暂时没有行动价值的问题，也值得留下。

### 2.1 逆向工程

先不看说了什么，只看怎么说、怎么构造。每个设计问到机制层：

- 不许说「这个设计不错」，必须说「它触发了什么机制」
- 机制必须落在**比对象更慢的变量层**（心理机制/数学结构/激励结构，而不是平台话术——战术月级变，规则年级变，人性十年级不变）
- 每个结论附「什么条件下失效」

### 2.2 过滤（学习的重点不是迁移，是过滤）

一个人的成功 = 可复制方法 × 不可复制条件。把后者剥掉：

- 剥掉：作者的出身、运气、时机、独有资源、平台红利、既有粉丝
- **过滤记录直接写进 boundary 字段**——「此方法在什么条件下成立」=「我滤掉了他的哪些特殊条件」
- 分不清是方法还是条件的 → `confidence: low`，留给验证环节裁决

### 2.3 AI 蒸馏

两问：**本质是什么？长期可复用的简洁框架是什么？**
入库的是这两句的答案，不是原文摘抄。

### 2.4 压块

每个对象最多 8-12 块，宁少勿多。块格式：

```yaml
id: ABS-xxxx
title: 一句话主张——必须是决策规则或机制，禁止「XX很重要」式描述句
type: principle / method / case / anti-pattern / insight / tool
mechanism: 为什么有效，落在慢变量层
usage_scene: 什么任务时调用
boundary: 什么条件下失效 + 过滤掉了作者的哪些特殊条件
confidence: high / medium / low
status: 候选            # 候选 → 自验通过 → 已转正
source: 出处 + 日期
serves: 服务于哪个能力/项目（爱马仕模块名或自己的场景）
```

## Phase 3: 移花接木（自验 = 闸门 3 上半）

- 从候选块挑 **1 块**，装进自己的真实场景，最低成本跑一次完整闭环
- 跑通 → `status: 自验通过`，在块里记录：在我的什么场景、做了什么改动、什么结果
- 跑不通 → **不删卡**，失效条件回填 boundary，confidence 降级。失败也是数据
- 节奏铁律：一次只移植一块。同时装三块，出了问题无法归因

---

## Phase 4: 市场验证（他验 = 闸门 3 下半）

自验通过的块，选一条出口，让别人付出真实代价来投票（注意力、时间、金钱都算）：

| 出口 | 形式 | 验证什么 |
|---|---|---|
| 做成 Skill | 封装给自己/他人长期调用 | 可复用性 |
| 发自媒体 | 把学习曲线本身写成内容（「我原来以为 A，后来发现关键是 B」） | 过滤是否干净——剥掉我的特殊条件后，别人还能看懂吗 |
| 发社群 | 给同频的人试用，收使用反馈 | 样本外有效性 |

规则：

- **每发一条内容，同步沉淀/更新一张块**——发布和入库是同一动作的两面
- 别人跑通 → `status: 已转正`（过滤干净的证明，顺带利他+变现）
- 别人跑不通但我跑得通 → boundary 里还藏着我的特殊条件，回 Phase 2.2 重新过滤
- 本 skill 停在发布物准备好为止，实际发布走执行接口——不代发、不代营销

---

## Phase 5: 回流

每完成一轮，追加一行 `小张外部知识库/学习课题/absorb-ledger.md`：

```markdown
| 日期 | 对象 | 压块数 | 自验 | 市场验证 | 边界修订 | 状态 |
|---|---|---|---|---|---|---|
```

- 已转正的块是否升格为**小张自己的洞见卡** → 按洞见卡入库标准（元子性+函数性）自检，转正由小张拍板。外部方法卡 ≠ 小张的洞见；从使用中长出自己的判断，那才是
- 90 天没被调用、没进过验证的候选块 → 移入归档（遗忘是筛选不是丢失）
- ledger 里同一来源连续多块验证失败 → 给这个来源整体降权，下次分诊时提示

---

## 边界

- 不替小张判断「什么值得学」——分诊只澄清卡点和层级，学不学小张定
- 对象是人 → `人物蒸馏器`；审决策 → 审核团；作品发布前评估 → 文章评委。不越界
- 不做收藏夹：分诊后决定不学的东西，登记一行出处即关闭，不进任何库
